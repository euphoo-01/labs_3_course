Где живут данные и кто выполняет SQL

Цель: объяснить путь простого SELECT и различить файлы БД, общую память и процессы.

1. База данных и экземпляр

База данных — файлы на диске. Экземпляр (инстанс) — SGA и фоновые процессы, которые обеспечивают работу с этими файлами. Остановка экземпляра освобождает его память, но не удаляет файлы базы.

SGA — System Global Area: общая память экземпляра. PGA — Program Global Area: личная память процесса, например для рабочих операций SQL. PGA не является частью SGA.

2. Три области, которые нельзя путать

Область SGAЧто хранит
Buffer cacheКопии блоков данных таблиц и индексов.
Shared poolОбщие структуры SQL/PLSQL, планы выполнения и кэш словаря данных.
Redo log bufferЗаписи об изменениях для восстановления.

3. Путь обычного чтения

SQL Developer → серверный процесс
                  ├─ shared pool: поиск пригодного разобранного SQL
                  └─ buffer cache: поиск нужных блоков
                       └─ при промахе: чтение с диска

Это базовая модель обычного чтения через кэш; существуют и другие пути, например direct reads. Listener помогает установить соединение, а SQL выполняет серверный процесс.

4. Что происходит при UPDATE и COMMIT

При изменении данных появляются изменённые (dirty) блоки и redo. DBWn записывает изменённые блоки в файлы данных. LGWR записывает redo в журналы. При обычном синхронном COMMIT Oracle ждёт сохранения нужного redo; все изменённые блоки таблицы к этому моменту не обязаны быть записаны DBWn.

5. Первая практика: только чтение

В SQL Developer выполняй запросы по одному. Не запускай пока весь DB_L5.sql: в нём есть удаление и повторное создание двух учебных таблиц.

SELECT SYS_CONTEXT('USERENV', 'CON_NAME') AS container_name,
       SYS_CONTEXT('USERENV', 'SESSION_USER') AS session_user
FROM dual;

SELECT name, value,
       ROUND(value / 1024 / 1024, 2) AS size_mb
FROM v$sga;

SELECT ROUND(SUM(value) / 1024 / 1024, 2) AS total_mb
FROM v$sga;

VALUE выражено в байтах. Деление на 1024² переводит результат в МиБ (в SQL названо MB). Сумма — выделенный объём SGA, а не свободная память. Ошибка доступа к V$SGA требует проверки прав; она не означает отсутствие SGA.

Проверь себя до открытия ответов

1. Где искать копию блока таблицы?
2. Кто пишет redo?
3. Значит ли COMMIT, что DBWn записал все блоки таблицы?

Сверить объяснение

1. В buffer cache. 2. LGWR. 3. Нет: устойчивость фиксации обеспечивается сохранением redo; блоки данных могут записываться позже.
