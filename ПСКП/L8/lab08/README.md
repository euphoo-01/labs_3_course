# лабораторная работа 8

Основа — лекция 06 «HTTP-сервер»: модуль `http`, события `data` и `end`, `querystring`, `fs`, `xml2js`, `xmlbuilder`, `multiparty`.

Запуск из этой папки:

```sh
npm install
npm start
```

Сервер: http://localhost:3000.

В условии встречаются опечатки: для query-параметров используется `&`, а корневой элемент XML-ответа закрывается тегом `</response>`.

Для задания 01 установить `/connection?set=2000`, затем отправлять запросы через одно keep-alive соединение. При паузе больше таймаута соединение закроется, следующий запрос создаст новое. В консоли выводятся открытие и закрытие соединений. Значение задаётся в миллисекундах и применяется к новым соединениям; современные версии Node.js могут добавлять небольшой буфер к таймауту сокета.

Для задания 07 в Postman выбрать GET, Body → raw и вставить текст размером около 1 МБ. Сервер выводит размер каждой порции в консоль, в ответе — число порций и общий размер. Границы порций определяет поток, поэтому они могут меняться. Также поддерживается POST на этот маршрут.

Для задания 02 открыть заголовки ответа в Postman или вкладку Network браузера: там будет `X-Lab: 08`.

Назначение заголовков, встречающихся при демонстрации:

- `Host` — адрес и порт сервера.
- `User-Agent` — сведения о клиенте.
- `Accept` — допустимые типы ответа.
- `Accept-Language` — предпочитаемые языки.
- `Accept-Encoding` — поддерживаемое сжатие.
- `Connection` — управление соединением, например `keep-alive`.
- `Keep-Alive` — параметры сохранения соединения, в том числе таймаут.
- `Content-Type` — тип содержимого и его кодировка.
- `Content-Length` — длина тела в байтах.
- `Transfer-Encoding: chunked` — передача тела порциями без заранее указанной длины.
- `Date` — время формирования ответа.
- `X-Lab` — пользовательский заголовок с номером лабораторной.
- `X-static-files-count` — количество файлов в `static`.
- `Origin` — источник запроса.
- `Referer` — адрес страницы, с которой выполнен переход или отправлена форма.
- `Sec-Fetch-Site`, `Sec-Fetch-Mode`, `Sec-Fetch-Dest`, `Sec-Fetch-User` — контекст запроса браузера: источник, режим, назначение и действие пользователя.
- `sec-ch-ua`, `sec-ch-ua-mobile`, `sec-ch-ua-platform` — сведения о браузере, мобильном устройстве и платформе.
- `Upgrade-Insecure-Requests` — предпочтение защищённого соединения.
- `Postman-Token` — служебный идентификатор запроса Postman.
- `Cache-Control` — правила кеширования.

## ответы на вопросы задания 15

1. `Content-Type` указывает MIME-тип тела сообщения, например `text/html`, `application/json`, `application/xml`; `charset` задаёт кодировку текста.
2. `Accept` сообщает серверу, какие MIME-типы ответа клиент готов принять.
3. `multipart/form-data` используют для отправки формы отдельными частями, в том числе файлов. Части разделяются строкой `boundary`, указанной в заголовке.
4. У формы задают `method="post"` и `enctype="multipart/form-data"`, а для выбора файла добавляют `<input type="file" name="file">`.
5. По умолчанию POST-форма использует `application/x-www-form-urlencoded`.
6. Параметры GET передаются в URI после `?` в виде `имя=значение&имя=значение`, специальные символы кодируются.
7. Параметры POST передаются в теле запроса. Формат определяется `Content-Type`: например, `application/x-www-form-urlencoded`, `multipart/form-data`, JSON или XML.
8. JSON — текстовый формат обмена данными. Поддерживает объекты, массивы, строки, числа, логические значения и `null`. Имена свойств и строки заключаются в двойные кавычки.
9. XML — текстовый язык разметки для структурированных данных. Данные представлены вложенными элементами с тегами и атрибутами; документ имеет один корневой элемент.
