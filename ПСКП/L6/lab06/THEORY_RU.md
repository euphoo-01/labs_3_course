# ЛР №06 (ПСКП). Теория и вопросы для защиты

## Главная идея работы

Понять, что такое **npm**, чем отличается **библиотека от приложения**, как загрузить внешнюю библиотеку **sendmail**, создать **свой npm-пакет** и использовать его через `require`. Отдельно продемонстрировать асинхронность SMTP-отправки.

## Кратко по заданиям

**Задание 01.** Командой `npm view sendmail` изучили пакет, `npm install` скачали его как зависимость, `npm ls sendmail` увидели установленную версию и дерево зависимостей.

**Задание 02.** Создали **один** HTTP-сервер `server.js` для всех задач. На GET `/06-02` выдаётся HTML-форма. Браузер посылает `POST /06-02/send` с полями отправителя, получателя и текста. Сервер проверяет данные, создаёт письмо и передаёт в `sendmail`. Результат показывает в браузере.

**Задание 03.** Написали собственный отдельный модуль `m0603`, экспортирующий только `send(message)`. Адрес получателя хранится константой модуля; функция принимает единственную строку и отправляет её на фиксированный email. Маршрут `/06-03` единого сервера импортирует локальный модуль из `./m0603`.

**Задание 04.** Подготовили `m0603/package.json`, проверку `npm pack --dry-run`, команды публикации `npm publish`. Маршрут `/06-04` единого сервера импортирует пакет из `06-04/node_modules` по имени (`requireFrom0604('m0603')`, то есть `require('m0603')` в контексте отдельного потребителя) вместо относительного пути. Предусмотрены установка из npm, удаление и глобальная установка; для публикации нужен реальный npm-аккаунт.

**Задание 05.** Ответы на контрольные вопросы приведены ниже.

## Ответы на контрольные вопросы из методички

### 1. Назначение npm?

**npm (Node Package Manager)** — менеджер пакетов для экосистемы Node.js/JavaScript. Позволяет находить, скачивать, устанавливать, удалять, обновлять и публиковать пакеты; управляет версиями зависимостей и запускает команды из `scripts` файла `package.json`. npm состоит из CLI и сетевого реестра npm registry.

### 2. Какие команды показывают установленные пакеты?

```bash
npm list            # локальные зависимости и их дерево
npm ls              # то же самое
npm ls --depth=0    # только зависимости верхнего уровня
npm ls sendmail     # сведения о конкретном пакете
npm ls -g           # глобальные пакеты
npm ls -g --depth=0 # только верхний уровень глобальных
```

`npm view sendmail` **не** показывает локально установленный пакет: команда обращается к реестру npm и показывает **опубликованный** пакет.

### 3. Что означает `-g`?

Флаг `-g` / `--global` означает **глобальную** установку/удаление/просмотр пакетов. Глобальная установка используется в первую очередь для CLI-инструментов (команды в терминале). Локальная устанавливает библиотеку в `node_modules` проекта и записывает зависимость в `package.json`, если используется `npm install package`.

**Важный нюанс защиты:** `require()` обычно не ищет модули в глобальном `node_modules`. Поэтому `npm install -g m0603` не гарантирует, что `require('m0603')` заработает. Для демонстрации возможна переменная `NODE_PATH` или явный импорт; обычно рекомендуют локальную установку.

### 4. Какие команды скачивают пакет?

```bash
npm install sendmail       # установить локально, добавить dependency
npm i sendmail             # короткая форма
npm install sendmail@1.6.1 # установить определённую версию
npm install               # установить все зависимости из package.json
npm install -g sendmail    # установить глобально
npm ci                    # чистая установка по package-lock.json (если он есть)
npm pack sendmail         # скачать tarball пакета, но НЕ установить
```

`npm install` обычно создаёт `node_modules`, обновляет `package-lock.json`. `npm ci` требует lock-файл и предназначена для воспроизводимых установок.

### 5. Для чего нужен `package.json`?

Это **манифест проекта/пакета** в формате JSON. Обычно содержит `name`, `version`, `description`, `main`, `scripts`, `dependencies`, `devDependencies`, `license`, `engines`. Нужен npm для разрешения зависимостей, запуска команд, упаковки и публикации пакета. В библиотеке `main` задаёт файл, загружаемый по `require('имя-пакета')`. `package-lock.json` фиксирует точные разрешённые версии дерева зависимостей.

### 6. Как опубликовать пакет?

1. Создать папку пакета и `package.json` (`npm init`).
2. Создать `index.js` с `module.exports = { send }` и указать `main`.
3. Выбрать свободное допустимое имя, например `@логин/m0603`; указать версию.
4. Выполнить `npm login`, предварительно зарегистрировавшись в npm.
5. Проверить состав архива с помощью `npm pack --dry-run`.
6. Выполнить `npm publish --access public` (для публичного scoped-пакета).
7. Проверить реестр через `npm view @логин/m0603` и страницу npmjs.com.
8. Для новой публикации повысить версию (`npm version patch`) и снова `npm publish`; уже опубликованную комбинацию имени+версии повторно публиковать нельзя.

## Дополнительные вопросы, которые часто задают

### Что такое Node.js?

Среда выполнения JavaScript вне браузера. Встроенные модули (`node:http`, `node:fs`) работают без npm; сторонние пакеты устанавливаются через npm.

### Что такое CommonJS и `require`?

**CommonJS** — система модулей Node.js: `require('./m0603')` импортирует код из относительной папки, `require('m0603')` — ищет пакет через алгоритм разрешения модулей (в том числе в `node_modules`). `module.exports = { send }` задаёт публичный интерфейс.

### Что возвращает `send(message)`?

`Promise`: SMTP-обмен асинхронен. При успешном callback из библиотеки Promise переходит в resolved; при ошибке — rejected. Используем `await` или `.then(...).catch(...)`, иначе ошибки можно не обработать.

### Как именно работает форма 06-02?

Браузер делает `GET /06-02`, сервер возвращает HTML. После отправки `<form method="post" action="/06-02/send">` браузер формирует тело `application/x-www-form-urlencoded`. Сервер читает тело запроса, разбирает `URLSearchParams`, проверяет адреса и строку. Затем вызывает библиотеку `sendmail` и возвращает HTML с сообщением об успехе/ошибке.

### Чем отличается HTTP от SMTP?

**HTTP** — обмен браузера с нашим веб-сервером (`GET`, `POST`, ответы 200/400/502). **SMTP** — передача электронного письма почтовым сервером (`EHLO`, `MAIL FROM`, `RCPT TO`, `DATA`). В задании приложение принимает данные по HTTP и передаёт сообщение по SMTP.

### Обязательно ли `sendmail` означает установленную в Linux программу `/usr/sbin/sendmail`?

**Нет.** В этой лабораторной `sendmail` — имя npm-пакета. Используется API `require('sendmail')()`; библиотека умеет работать с SMTP напрямую (в частности через `devHost`/`devPort`). Похожее имя имеет отдельная Unix-программа, но это не одно и то же.

### Почему письмо может не прийти, если программа не показала ошибку?

Принятие SMTP-сервером не означает окончательной доставки. Возможны ограничения на исходящие SMTP-подключения, неверный DNS, антиспам, отсутствие SPF/DKIM, фильтрация получателем. Для воспроизводимой демонстрации пользуйтесь локальным SMTP-приёмником `scripts/smtp-capture.js`.

### Чем отличается `dependencies` от `devDependencies`?

`dependencies` нужны приложению в работе (здесь `sendmail`). `devDependencies` — пакеты только для разработки и тестов. Здесь тесты используют встроенный `node:test`, поэтому внешних тестовых зависимостей нет.

### Зачем `npm pack`, если есть `npm publish`?

`npm pack --dry-run` показывает файлы, которые попадут в опубликованный архив, без публикации. Это помогает не включать в пакет лишние файлы или секреты.

### Что означает `name`, `version`, `main` и `files` в нашем пакете?

- `name`: идентификатор пакета (`@your-npm-username/m0603` до замены).
- `version`: семантическая версия, например `1.0.0`.
- `main`: точка входа `index.js`, импортируемая через `require`.
- `files`: список файлов, которые будут включены в публикуемый архив.

### Почему 06-03 использует `require('./m0603')`, а 06-04 — `require('m0603')`?

В 06-03 демонстрируется **локальный модуль прямо из исходников**: в `server.js` написано `require('./m0603')`. В 06-04 — **отдельно установленный npm-пакет**, доступный в `06-04/node_modules` по имени. Поскольку сервер один и расположен в корне, используется `createRequire` с путём к `06-04/package.json`, чтобы разрешить имя `m0603` как будто импорт выполнен из папки 06-04. Это ключевое отличие заданий.

### Отличие dry-run и локального SMTP?

`MAIL_DRY_RUN=1` вообще **не вызывает отправку** и выводит объект письма в консоль — удобно без зависимостей и интернета. При `MAIL_DEV_PORT=1025` библиотека `sendmail` действительно устанавливает SMTP-соединение, но с **локальным** учебным SMTP-приёмником, который не пересылает письма наружу. Для демонстрации работы библиотеки второй вариант убедительнее.

## Почему теперь только один сервер? Как работают endpoints?

**Один сервер** создаётся в `server.js` через `http.createServer` и слушает **один порт 3000**. URL состоит из пути и HTTP-метода. В таблице `routes` маршруты `/06-02`, `/06-03`, `/06-04` связываются со своей HTML-страницей, валидатором и обработчиком отправки. `GET` отдаёт страницу, `POST /06-XX/send` запускает соответствующее задание. Не нужны три отдельных процесса, поэтому преподавателю удобно переключаться по ссылкам.

**Почему 06-04 работает через `createRequire`?** `require('m0603')` ищет пакет относительно **файла, который его вызывает**. Если вызвать его просто из корневого `server.js`, поиск пойдёт в корневой `node_modules`, а не в `06-04/node_modules`. `createRequire(pathTo0604PackageJson)` создаёт функцию импорта, выполняющую разрешение зависимостей **как если бы вызывающий файл находился в 06-04**. Это не меняет сам пакет и сохраняет честную демонстрацию установки из npm.

**Что говорить за 30–40 секунд:** «Я использовал один HTTP-сервер на порту 3000. Для каждого задания есть отдельный GET для HTML-формы и POST для отправки. 06-02 использует npm-пакет sendmail напрямую. 06-03 вызывает `send(message)` из моего локального модуля m0603. В 06-04 я устанавливаю этот модуль с помощью npm и подключаю его по имени из node_modules через createRequire. Модуль самостоятельно хранит адрес получателя и экспортирует ровно одну функцию. Для проверки есть режим без отправки и локальный SMTP-сервер».
