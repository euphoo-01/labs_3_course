# ПСКП — лабораторная работа №06 (единый сервер Node.js)

Вместо трёх отдельных HTTP-серверов используется **один `server.js`, один порт 3000**, а каждое задание имеет свои GET/POST endpoints. Исходники npm-пакета `m0603` остаются в **отдельной папке**, как требует лабораторная. `THEORY_RU.md` — вопросы и короткие ответы для защиты.

Требования: Node.js 18+, npm. Веб-сервер написан на встроенном модуле `node:http`, почта — через npm-пакет `sendmail`.

## Быстрый запуск

```bash
# из папки lab06
npm run setup    # установка зависимостей корня и отдельного потребителя 06-04
npm test         # 8 автоматических тестов
npm run demo     # один сервер: имитация отправки, без SMTP
```

Откройте **http://127.0.0.1:3000**: там меню всех заданий. Можно открывать ссылки непосредственно:

| Что показать | GET-страница | POST формы | Реализация |
|---|---|---|---|
| 06-02 | `http://127.0.0.1:3000/06-02` | `/06-02/send` | `lib/mail.js → sendmail` |
| 06-03 | `http://127.0.0.1:3000/06-03` | `/06-03/send` | `require('./m0603').send(message)` |
| 06-04 | `http://127.0.0.1:3000/06-04` | `/06-04/send` | установленный `m0603` из `06-04/node_modules` |

Остановить сервер: `Ctrl+C`. **Всё обслуживает один процесс**: команды `start:02`, `start:03`, `start:04`, `demo:02` и т. п. больше не нужны. `npm start` запускает тот же сервер, но без имитации отправки.

Если npm-пакеты пока не установлены, `npm run demo` всё равно позволит показать **06-02 и 06-03**. Для **06-04 сначала установите пакет** в папку `06-04`: `npm --prefix 06-04 install`.

## Как работает один сервер

В `server.js` в `createServer()` создана таблица маршрутов (`Map`). Она связывает **путь** со страницей, функцией проверки и функцией отправки:

- При **`GET /06-02`** сервер читает нужную HTML-форму и отдаёт её браузеру. Аналогично для `/06-03` и `/06-04`.
- При **`POST /06-02/send`** сервер обрабатывает `URLSearchParams`, проверяет два email и текст, затем вызывает `sendEmail(letter)` из `lib/mail.js`.
- При **`POST /06-03/send`** сервер передаёт только одну строку в `send(message)` из **локального** `./m0603`.
- При **`POST /06-04/send`** сервер передаёт одну строку в `send(message)` из **npm-установленного** `06-04/node_modules/m0603`.

Для 06-04 используется `createRequire('.../06-04/package.json')`: поскольку HTTP-сервер теперь находится **в корне**, обычный `require('m0603')` из `server.js` искал бы пакет не в той папке. `createRequire` позволяет выполнять `require('m0603')` с путями поиска потребителя 06-04 и тем самым сохранить различие между заданиями 03 и 04. Пакет **не импортируется из `./m0603`** в обработчике 06-04.

## Задание 02 — форма email

Откройте `/06-02`, заполните три поля, нажмите «Отправить». В режиме `npm run demo` письмо выводится в консоль, а браузер показывает, что это **тест**, не реальная доставка.

Для реальной SMTP-попытки:

```bash
npm start
```

Для отправки в учебный локальный SMTP-приёмник вместо интернета откройте два терминала:

```bash
# терминал 1
npm run smtp:dev
```

```bash
# терминал 2 (Linux/macOS)
MAIL_DEV_PORT=1025 npm start
```

В PowerShell для терминала 2:

```powershell
$env:MAIL_DEV_PORT = '1025'
npm start
```

При отправке через форму в первом терминале появится содержимое письма. Это **реальный вызов `sendmail` и SMTP**, но письмо не уйдёт во внешний мир.

## Задание 03 — свой модуль `m0603`

В `m0603/index.js` определены константы:

```js
const FIXED_RECIPIENT = 'student@example.test';
const FROM_ADDRESS = 'sender@example.test';
```

Перед реальной отправкой замените их на свои адреса. Функция `send` принимает **ровно один аргумент-строку**, использует фиксированный адрес получателя и возвращает `Promise`:

```js
const { send } = require('./m0603');
await send('Привет из задания 03!');
```

Откройте `/06-03` или запустите консольное демо: `node scripts/dry-run.js 06-03/demo.js`.

## Задание 04 — публикация и установка npm-пакета

**Опубликовать без вашего npm-аккаунта нельзя.** Для публикации:

1. В `m0603/package.json` измените `@your-npm-username/m0603` на `@ВАШ-ЛОГИН/m0603`.
2. В `m0603/index.js` установите собственные адреса отправителя и получателя.
3. Выполните:

```bash
cd m0603
npm login
npm pack --dry-run
npm publish --access public
npm view @ВАШ-ЛОГИН/m0603 version
cd ..
```

По умолчанию потребитель в `06-04/package.json` устанавливает пакет из локальной папки (`file:../m0603`), чтобы можно было демонстрировать **до** публикации:

```bash
npm --prefix 06-04 install
npm run demo
# далее откройте http://127.0.0.1:3000/06-04
```

После публикации замените локальную зависимость установленной из реестра:

```bash
cd 06-04
npm uninstall m0603
npm install m0603@npm:@ВАШ-ЛОГИН/m0603
npm ls m0603
cd ..
npm run demo
```

`m0603@npm:@ВАШ-ЛОГИН/m0603` — npm alias: опубликованный scoped-пакет устанавливается под импортируемым именем `m0603`. Если сервер уже работает и версия пакета изменилась, перезапустите сервер.

Удаление и глобальная установка (для вопросов по теории):

```bash
cd 06-04
npm uninstall m0603
cd ..
npm install -g m0603@npm:@ВАШ-ЛОГИН/m0603
npm ls -g m0603 --depth=0
```

Глобальные библиотеки обычно **нельзя** импортировать через простой `require('m0603')`, потому что Node.js по умолчанию не ищет глобальный `node_modules`. Отдельное консольное демо с `NODE_PATH` есть ниже:

```bash
# Linux/macOS
NODE_PATH="$(npm root -g)" MAIL_DRY_RUN=1 node 06-04/demo.js
```

```powershell
# Windows PowerShell
$env:NODE_PATH = (npm root -g)
$env:MAIL_DRY_RUN = '1'
node 06-04/demo.js
```
